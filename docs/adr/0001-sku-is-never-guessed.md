# SKU 只由字典和人裁决，代码不猜

状态：已采纳

OCR 会把 SKU 读错，但"改错一个真的 SKU"没有人会发现，而"漏改一个"会在核对列表里被人看到。两种错的代价不对称，所以纠错只认有把握的情况，拿不准的都留给人或字典。

- **形近字符只在段内已有真数字时才推**（`O1` → `01`）。从前还做两件事，都因为毁的比救的多删掉了：尾段两解时一律当流水号（`MCH-SS` 被毁成 `MCH-55`，`PHC-ELE-BS` 被毁成 `-85`）；反向的 0→O、1→I 整段推断（`V2` → `VZ`，`A1B` → `AIB`，`80-` → `BO-`）。代价是 `8K` → `BK` 这类首字符误读不再自动纠，交给 `learned.py` 的字典。
- **模糊匹配只认形近等价类**（`learned._CONFUSE_GROUPS`）。`WLA` 和 `WLB` 是两个真实存在的型号，不许互相靠。
- **含空格的 SKU 只认字典命中**。`MCH-SS` + `V2` 只有字典里确实有 `MCH-SS V2` 才合并：空格既可能是列分隔符，又可能是 SKU 里的字符，没有规则分得干净，猜错会把 `US-PRO-06` 和数量列 `1` 粘成假 SKU。
- **学到的纠错只作用在图片路径上**。粘贴文本是人敲的，没有形近错，拿字典去动它会重蹈 3aac5c5 的覆辙（`80-SS-BK` → `BO-SS-BK`）。
- **建议不自动生效**：界面只在 SKU 格下面挂一条小字，由人采纳。
- **删一行时当场问一句**：「误识别」和「这单不打」在操作上分不开，而把真 SKU 学成垃圾，以后会静默少打标签。
